# 客户部署网络与代理验收清单

记录日期：2026-10-18。状态：交付前必须验收，未在客户机器完成。

## 原则与边界

- 客户计划局域网部署，主机为Apple Silicon Mac。员工通过LAN访问蓝乐，不依赖公网穿透；主机休眠、关机或LAN断开仍会影响使用。
- 区分三条链路：员工浏览器到蓝乐、蓝乐到AI供应商、供应商到音乐回调。不能用“网页能打开”代替其余两条链路验收。
- 换代理软件、节点、TUN模式、DNS模式、Wi-Fi或网段可能影响AI调用与穿透，不代表一定故障，也不能保证现有兼容覆盖所有代理。
- 当前文本/音频Fake-IP兼容有明确触发条件和安全边界，不是通用网络修复；Windows成功不等于Mac已验收。默认不关闭TLS证书校验、不擅自更换供应商地区或转发密钥。

## 交付前配置

- [ ] 确定主机稳定LAN地址（优先路由器DHCP地址保留），记录员工入口；前端/API使用正确LAN监听、同源代理及必要防火墙规则，不将127.0.0.1当员工入口。
- [ ] 数据库、Redis和管理端口不向公网开放；按需限制LAN暴露，员工只访问应用入口。
- [ ] 记录客户实际代理软件、TUN开关、DNS模式及需要代理的域名；不记录订阅链接、节点密码、API Key或Token。
- [ ] LAN/本机通信不走外部代理；文本、音乐、音频下载和公网回调/隧道按实际网络分别验证，不简单将全部流量强制直连或全部代理。
- [ ] 根据现场故障决定是否启用`AI_FAKE_IP_FALLBACK`和`MUSIC_DOWNLOAD_DOH_FALLBACK`，不无条件复制开发机配置。
- [ ] 音乐供应商无法访问私网IP。选择固定公网回调入口、持久隧道或中继；临时trycloudflare网址仅用于演示，不作为正式可用性承诺。
- [ ] 固定入口仍需验证自动重连和开机启动；域名固定不代表进程永久在线。保留回调签名校验，明确公网方案的账号归属、费用和维护人。
- [ ] 使用客户生产凭证，妥善保存加密配置；上线前吊销开发Kimi密钥。任何网络变更不得通过关闭证书验证来“修复”。

## 必测场景

每项记录实际时间、环境、结果、诊断编号和处理方式；需要消耗供应商额度的测试先由客户确认。

| 场景 | 通过标准 |
|---|---|
| 代理开启/关闭 | LAN登录、历史记录、已归档音频可访问；AI接口返回真实成功或明确原因，不能假成功。 |
| 更换节点、切换TUN/DNS模式 | 测文本连接、音乐提交/查询/回调、音频归档与播放；明确哪些链路受影响，不要求无条件全部直连成功。 |
| 切换Wi-Fi、网段或物理网卡 | 本机绑定不残留旧IP；LAN入口变化可定位；确认Mac实际网卡识别和隧道参数。 |
| 主机重启 | 应用、数据库、两个worker和固定回调链路按方案恢复，不需手工清理Docker临时目录；检查休眠策略。 |
| 暂时断网、代理重连 | LAN不随公网入口失效；任务状态最终可核对，不重复提交收费生成，不长期假“运行中”。 |
| 重复/延迟/无效回调 | 有效回调幂等，无效签名被拒；回调延迟或中断后任务可按恢复机制核对。 |
| 供应商429/余额不足/密钥无效 | 区分繁忙、限流、欠费、权限等，不盲目重试、不静默更换模型。 |
| 隧道进程存在但未连接 | 不报告“已启动成功”；检查连接注册及外部HTTPS/API健康，而不只检查PID或打印出的网址。 |
| 五账号实际使用 | 登录、队列、试听和跨页操作正常；每账号限额与音乐串行符合约定，等待时间和外部服务延迟可解释。 |

## 故障排查顺序

1. 先分辨LAN应用不可达、只有公网不可达，还是网页正常但AI功能失败。
2. 检查本地前端/API/数据库/worker，再查公网隧道注册状态和外部HTTPS健康。
3. AI失败核对实际启用接口、供应商响应码、TLS/DNS/代理诊断，不直接让客户充值或换Key。
4. 更换临时入口必须同步音乐回调根地址；正式固定入口避免频繁改地址，但仍需监测连接。
5. 不为排查随意停止客户全部代理、删除数据库/Docker卷或重复提交生成任务。
