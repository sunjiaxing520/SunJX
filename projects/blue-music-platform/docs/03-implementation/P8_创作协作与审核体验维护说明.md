# P8 创作协作与审核体验维护说明

更新时间：2026-08-15

## 目标

P8 在既有“榜单 -> 分析 -> 作词 -> 音乐创作”主链路上补齐团队挑选、歌词迭代和
审核协作能力。它不改变各类原始产物的归属：报告、歌词版本和音乐结果仍由各自
模块保存；收藏、预览和审核只保存关联关系、操作记录或新的正式版本。

## 收藏夹分级

`favorite_items` 的 `target_type` 标识产物类型，`category` 标识团队精选等级：

```text
unclassified（待分类） / S / A / B / C / D
```

分析报告、歌词版本和音乐结果都可以进入任一级。收藏页先按等级切换，随后可按
产物类型过滤；可查看来源、产出时间、收藏时间、创建人和隐藏备注。变更分级或
备注不会改写原始报告、歌词或音频结果。

主要接口：

```text
GET   /api/v1/favorites?category=...
POST  /api/v1/favorites
PATCH /api/v1/favorites/{favorite_id}
DELETE /api/v1/favorites/{favorite_id}
```

## 双榜单采集与分析

酷狗适配器目前支持两张榜单：

| 榜单 | `chart_code` | 页面行为 |
|---|---:|---|
| TOP500 | `8888` | 每日快照，供连续日期趋势分析 |
| 飙升榜 | `6666` | 当前上升最快列表，可选单曲直接分析，不计算多日趋势 |

同一自然日的同一榜单会覆盖旧快照并更新时间；不同榜单各自保存。分析服务构造
上下文时同时过滤快照日期与榜单代码，避免 TOP500 和飙升榜彼此污染。工作流的
采集步骤同样保存榜单选项，并将对应快照编号继续传给分析步骤。自动流程选择飙升榜
时可设置目标名次，默认第 1 名；系统至少采集到目标名次，但只把该名次单曲传给分析。

## 歌词 AI 助手

歌词页的分析方向选择器是当前页面内的分级抽屉，按 `待分类 / S / A / B / C / D`
展示全部已加载分析以及收藏中的旧分析。界面显示用户可对应到分析记录的任务编号，
内部仍以报告编号提交。选择方向后自动填写主题、关键词、曲风、情绪、场景、速度、
人声和结构要求，用户检查修改后再提交。生成后的歌词版本可以发起多轮 AI 助手对话：

```text
LyricsVersion
-> 用户提出修改要求
-> AI 返回预览文本和说明
-> 可继续提要求
-> 用户确认某条预览
-> 创建新的 LyricsVersion
```

预览历史写入 `lyrics_assistant_messages`。预览不是正式产物，只有确认接口会保存
新版本；因此旧版本、收藏和下游音乐任务都不会被对话直接覆盖。

```text
GET  /api/v1/lyrics/versions/{version_id}/assistant
POST /api/v1/lyrics/versions/{version_id}/assistant
POST /api/v1/lyrics/assistant-previews/{message_id}/confirm
```

## 审核智能体

审核智能体首先用于歌词审核，但架构保留给后续其他审核对象。

1. 超级管理员在创建对话中描述人设、评分标准、禁忌和输出格式，先获得初始化
   预览，再创建智能体。
2. 管理员显式分配成员。成员权限区直接加载全部启用中的成员账号，以响应式复选网格
   显示已有选择和选中数量，支持多选与取消后统一保存；不得改回依赖弹层的多选下拉框。
   无成员权限的用户不能对该智能体发起审核或读取记录。
3. 管理员能查看完整记忆和初始化记录；成员只能读取简短的记忆概述。
4. 日常审核不自动改写记忆。用户需要主动点击“保存记忆”，输入要沉淀的内容，
   系统才调用文本 Provider 做归纳与去重。
5. 每个审核智能体拥有独立 `pass_score`，创建时默认 80；管理员可调整，成员可查看。

```text
POST /api/v1/review-agents/initialize-preview
POST /api/v1/review-agents
GET  /api/v1/review-agents
GET  /api/v1/review-agents/{agent_id}
PUT  /api/v1/review-agents/{agent_id}/members
PATCH /api/v1/review-agents/{agent_id}/settings
GET  /api/v1/review-agents/lyrics-options
POST /api/v1/review-agents/{agent_id}/reviews
GET  /api/v1/review-agents/{agent_id}/reviews
GET  /api/v1/review-agents/{agent_id}/reviews/{review_id}/assistant
POST /api/v1/review-agents/{agent_id}/reviews/{review_id}/assistant
POST /api/v1/review-agents/{agent_id}/reviews/{review_id}/assistant-previews/{message_id}/confirm
POST /api/v1/review-agents/{agent_id}/memory
```

相关表：`review_agents`、`review_agent_members`、`review_runs`。响应模型在成员
视角不会返回完整 `memory_detail` 或 `initialization_notes`；这项限制必须同时由
服务层和接口测试守护，而不能只依靠前端隐藏。

每条审核记录顶部都有审核作用域内的歌词 AI 修改入口。服务层先校验当前用户拥有该
审核智能体权限，再校验 `review_id -> agent_id -> lyrics_version_id` 关系；生成时把
审核总结、维度、扣分原因、建议和风险作为 `review_guidance` 注入现有歌词修改
Provider。预览继续复用 `lyrics_assistant_messages`，并由可空的 `review_run_id` 区分
普通歌词对话和每一份审核对话；确认后复用歌词版本服务创建新的正式版本并设为当前
作品。这里的“当前作品”是版本指针变化，不删除或物理覆盖旧版本。

确认接口还必须同时校验 `message.review_run_id` 和 `message.source_version_id`。因此同一
歌词版本即使产生多份审核记录，各自的对话也不会混合，同一个用户也不能拿另一条对话
预览串到当前审核中保存。审核智能体成员通过这组审核作用域接口完成修改，无须绕回
普通作词页的 Agent 权限。

### 自动流程中的审核

审核智能体既可以在独立页面手工调用，也可以作为自动流程中“歌词创作”和“音乐
创作”之间的可选步骤。模板保存审核智能体和补充审核要求；及格线读取审核智能体自身
设置。启动模板和恢复暂停流程时都会重新校验当前操作者对该智能体的权限。

每次进入审核步骤只创建一条正式 `review_runs` 记录。未达标时工作流立即进入
`paused`，保存总分、扣分原因、修改建议、审核记录编号和歌词版本；系统不自动调用
歌词 AI，也不自动开始第二次审核。达到及格线时才把当前歌词版本传给下游。

暂停后的人工决定包括：接受当前版本继续、输入要求让 AI 修改、在歌词页手工修改后
重审、直接重新生成。后三种操作每次只触发一次新审核，如果仍不合格便再次暂停；
接受操作不会伪造审核通过，只会明确记录为用户接受。暂停期间不会自动超时失败，
也不能删除或并行启动另一条全局流程。

## 音乐任务参数与授权改编

音乐创作表单使用标签输入目标风格和避免风格。服务端标准化标签、拒绝交集，并
把实际标签、活动模型、生成/改编来源和权利确认写入 `music_tasks`。管理员通过
音乐设置切换活动模型，默认 `v4.5`；旧任务保持创建时的模型记录。

授权改编必须由提交者勾选权利确认，填写可追溯的来源说明。该动作只在当前
Provider 支持的范围内调度，失败时如实进入任务记录；不得把改编入口表述为可对
第三方作品进行未授权复制或模仿。

音乐结果卡保持紧凑：试听、查看歌词、下载、重新生成、删除、收藏。歌手模型
替换作为预留入口禁用显示；没有可靠时长时显示“时长待供应商返回”，不得显示
`NaN:NaN`。

主要接口：

```text
GET  /api/v1/music/settings
PUT  /api/v1/music/settings             # 超级管理员
POST /api/v1/music/tasks/{task_id}/regenerate
POST /api/v1/music/adaptations
```

## 工作台界面规则

前端按内部操作台而非营销站设计。侧栏固定分为“总览、创作流程、资产与协作、
系统管理”，顶部只保留当前模块和账号入口；工作台提供自动流程、榜单采集、歌词
创作和音乐试听的快捷命令。页面区块使用分隔带，只有表单、列表、任务详情等真正
需要边界的工具使用不超过 8px 的圆角容器。

自动流程在宽屏显示五步流水线，在中等桌面宽度按 `3 + 2` 排列，在手机上单列；
配置保存与运行按钮固定在表单底部。作词页的分析引用入口占据整行，生成按钮同样
固定在表单底部。审核智能体的长记忆概述默认折叠，完整记忆继续只在管理员折叠区
展开；成员权限名单在有界小框内按宽度自动排列，成员较多时只滚动名单本身。所有长
历史仍遵守“默认展示最新记录、按需展开”的规则。最近审核的每条记录默认只显示
审核编号、时间、模型、通过状态和分数；摘要、维度评分、优点、扣分原因、修改建议与
风险提示统一放在可独立展开和隐藏的审核结果区域中。每条记录的 AI 修改区位于标题与
折叠按钮之间，报告收起时仍可输入要求；对话和歌词预览限制在内部滚动区域，避免历史
增长后撑长整个页面。用户检查预览后必须主动点击保存按钮，页面才把新版本标记为当前
作品。

全局视觉令牌位于 `frontend/src/main.tsx`，结构和响应式样式位于
`frontend/src/index.css`。修改核心页面后至少检查 `1200px` 桌面和 `390px` 手机
宽度，确保侧栏或抽屉可导航、按钮文字不截断、正文无横向溢出，表格只在自身容器
内滚动。
