# P8.1 上游产出选择器维护说明

## 目标

手工创作链路经常需要引用上一环节产出。数据增多后，长文本下拉框无法同时承担
定位、比较和核对，因此前端统一采用以下交互：

```text
紧凑当前选择
-> 打开页内 Drawer
-> 搜索或按业务分组缩小范围
-> 左侧选择预览候选
-> 右侧核对完整内容
-> 明确确认后写回当前表单
```

预览候选和已经提交给表单的选择是两个状态。浏览不同候选不得偷偷改变表单；关闭
面板也不得提交预览中的内容。

## 代码边界

```text
frontend/src/components/UpstreamOutputPicker.tsx
  UpstreamOutputField       当前选择的紧凑摘要
  UpstreamOutputPicker      搜索、分组、列表、预览和明确确认
  UpstreamOutputItem        跨业务统一展示契约

frontend/src/lib/upstreamOutputs.ts
  buildLyricsOutputItems    歌词版本 + 收藏等级 -> 统一契约
  FAVORITE_OUTPUT_GROUPS    待分类/S/A/B/C/D 分组

frontend/src/components/LyricsOutputPreview.tsx
  歌词风格和完整正文预览

frontend/src/index.css
  upstream-output-*         桌面与手机响应式样式
```

通用组件不请求接口、不理解榜单或歌词模型，也不直接修改表单。页面适配层负责准备
`items`、加载业务详情，并在 `onConfirm` 中写回编号和派生字段。

## 已接入的数据边

| 手工环节 | 候选来源 | 确认后写回 | 详情预览 |
|---|---|---|---|
| 榜单采集 -> 内容分析 | `listRankingSnapshots` | `snapshot_id` | 按需读取该快照前 10 首 |
| 内容分析 -> 歌词创作 | `buildLyricsAnalysisDirections` | `report_id + direction_index`，并自动填完整创作参数 | Hook、主题、人声、结构、避免项 |
| 歌词创作 -> 审核智能体 | `listReviewLyricsOptions` + 歌词收藏 | `lyrics_version_id` | 风格要求和完整歌词 |
| 歌词创作 -> 音乐创作 | 作词任务版本 + 歌词收藏 | `lyrics_version_id`，并填标题和风格提示 | 风格要求和完整歌词 |

分析方向的展示来源必须写成“榜单分析任务号 + 报告号 + 方向号”。页面内部选择值仍为
`report_id:direction_index`，不能把用户看到的 `AnalysisTask.id` 错当成接口需要的
`AnalysisReport.id`。

审核歌词候选接口返回主题、正文、风格、当前版本状态、供应商和模型，因此前端不需要
为每次预览再拼接其他任务接口。该接口当前最多返回最近 100 个版本；数据规模显著增大
后，应在保持本组件契约不变的前提下给后端增加搜索和分页。

## 分组语义

- `最近产出`：当前加载范围内的全部候选，按来源接口既有的新旧顺序展示。
- `待分类/S/A/B/C/D`：歌词或分析产出的团队收藏等级视图；尚未收藏或未分级的产出
  进入待分类，不创建副本。
- `TOP500/飙升榜`：榜单快照的业务类型视图，不混合趋势计算。
- 搜索同时覆盖标题、来源编号、摘要、标签、元数据和页面提供的扩展搜索文本。

## 交互约束

1. 点击候选只更新右侧预览，`onConfirm` 只能由底部确认按钮触发。
2. 当前已选项必须在列表中明确标记，关闭面板后仍显示在紧凑字段中。
3. 列表只显示短摘要；完整歌词、分析参数或歌曲明细放在可滚动预览区。
4. 桌面使用左右比较布局，手机改为列表在上、预览在下，页面不得横向溢出。
5. 空数据、加载中和搜索无结果分别显示明确状态。
6. 自动工作流不使用本组件，继续由后端传递 `snapshot_id -> report_id -> lyrics_version_id`。

## 扩展步骤

新增另一条手工上游选择时：

1. 在页面或领域 `lib` 中把源数据映射为 `UpstreamOutputItem[]`。
2. `source` 填完整来源链；`summary` 保持可扫描；完整内容交给 `renderPreview`。
3. 只有确实存在业务分类时才传 `groups`，不要把接口状态随意当成收藏等级。
4. 在 `onConfirm` 中写回稳定数据库编号，并补齐该页面需要自动填充的字段。
5. 增加测试，至少锁住搜索/分组、预览不提交、明确确认三个行为。
