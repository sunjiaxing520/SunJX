```text

自动审核的数据边：lyrics_version_id -> 单次 review_run -> 通过/paused；不得无人值守循环
独立审核修改边：review_run -> review_guidance -> assistant preview -> 用户确认 -> 当前 LyricsVersion；旧版本保留
paused 审核决定：接受当前版本，或明确打回/读取手工最新版本/重新生成后只复审一次
歌词 AI 助手的数据边：lyrics_version_id -> assistant preview -> 用户确认 -> 新 lyrics_version_id
手工上游选择边：候选列表 -> 详情预览（不写表单）-> 用户明确确认 -> 稳定数据库编号写回
审核智能体的长期记忆只由显式保存操作写入；成员不能读取完整记忆
官方/兼容实现切换只影响新任务；已有任务保持创建时的实现
兼容服务 Cookie 不进入蓝乐；hCaptcha 触发后失败暂停并等待人工验证
```

## 5. 故障知识节点

| 现象 | 已知判断 | 当前处理 |
|---|---|---|
| “无法连接后端” | 请求未到 FastAPI，或恰逢重启 | 先查 8000 和两个健康接口，再查进程与 CORS |
| 智谱 `429/1302` | 账户在途并发或速率限制 | 单次等 180 秒；读取超时不重复；无 Retry-After 不自动重试 |
| Kimi 余额显示错误 | 官方余额接口、密钥或网络暂时不可用 | 不影响任务执行；检查活动配置和 Kimi 控制台后刷新 Dashboard |
| 音乐任务永久“运行中” | worker 在外部调用期间中断 | 超时后恢复为 pending 并重新入队；已有外部任务编号时继续查询 |
| 自动流程停在 `paused` | 单次歌词审核低于所选智能体及格线，属于等待人工决定，不是崩溃 | 查看扣分原因和建议，再选择接受、打回 AI、手工修改后重审或重新生成；系统不会自行继续 |
| `SUNO_HUMAN_VERIFICATION_REQUIRED` | Suno 主动要求 hCaptcha | 管理员在正常网页验证、更新隔离会话，再点“重新入队” |
| `SUNO_COOKIE_NOT_CONFIGURED` | GitHub 兼容服务已启动但尚未配置登录会话 | 在本机运行隐藏输入脚本，重启兼容服务，再刷新状态和额度 |
| 歌词段落缺 `content` | 模型结构不完整 | 严格段落 Schema，记录 `LYRICS_PROVIDER_FAILED` |
| 分析速度为 `medium-fast` | AI 别名超出 API 枚举 | 统一归一为 `fast`，旧报告读取时兼容 |
| Docker 不运行 | 可能处于游戏模式或虚拟化关闭 | 切开发模式并重启，再检查 Docker Desktop |

## 6. 不得遗忘

- 不保存或输出真实密码、Token、API Key。
- 不回滚其他 Agent 或用户的改动。
- 不把免费开发模型直接承诺为生产方案。
- 不把元数据推断描述成真实音频检测。
- 不为“看起来成功”而吞掉外部错误。
- 不让工作流或其他 Agent 直接调用 Suno 底层实现。
- 不接入 2Captcha 自动代答、浏览器指纹规避或验证码绕过。
- 不为有限预算提前实现拖拽 DAG、分支并行、总调度 AI、任意循环、复杂记忆或多 Agent 市场；审核步骤必须保持单次调用和人工确认边界。
- 客户部署前必须吊销当前 Kimi 开发测试密钥，并使用独立生产密钥重新验收。

## 8. 图谱维护规则

1. 本文件只保留**当前有效事实**，不追加流水账。

4. 故障解决后只留下可复用判断，不粘贴长堆栈。
5. 密钥和账号凭据永远不进入图谱。
6. 每次阶段切换、供应商切换、运行方式变化或测试基线显著变化时更新。
